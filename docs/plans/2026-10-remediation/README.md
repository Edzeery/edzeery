## 2) قواعد صارمة قبل البدء بأي مهمة

1. **لا تنفيذ قبل موافقة صريحة.** كل مهمة تُعرض أولًا كخلاصة + ملف التوثيق + نطاق الملفات، ثم يُنتظر الموافقة.
2. **اقرأ الوثيقة المرجعية لكل مهمة أولًا** ثم صِغ التغيير وفقها (لا تخترع أنماطًا جديدة). راجع الجدول في نهاية كل ملف.
3. **راجع `00-quality-gates.md` قبل أي تعديل UI/CSS/Blade** — أي تعديل يخالف البوابات يُرفض.
4. **كل تغيير يمر بـ:**
   - `php -d memory_limit=-1 vendor/bin/pest` — قبل وبعد.
   - `vendor/bin/pint` (تنسيق) — بعد.
   - إن وُجد: فحص `dark:`/`#hex` حسب القواعد.
5. **لا تلمس `.env` ولا تُدخل أسرارًا** في أي ملف يتتبعه git.
6. **أي إصلاح ينتهي بتحديث `STATUS.md`** (رقم المهمة/تاريخ/دليل التحقق).

## 5) حالة المنظومات الحالية (خلاصة ما توصل إليه الفحص)

- **أمان:** 🔴 لا — RCE عبر `HasInlineEdit::saveEdit`؛ سرقة حساب عبر `StoreTeamService`؛ IDOR عبر معاملات Livewire النموذجية؛ رفع عشوائي؛ دخول بلا حماية.
